## 维护约定

- 每次改动单独一次 commit，message 写清「改了哪一节 + 为什么」。例：`docs: 补充沟通风格，加一条不要编造数据`。
- 大改动先开 Issue 说清楚，提交时带上 Issue 编号。
- 看历史：`git log --oneline`，或仓库页面的 History。回退某一次：`git revert <commit-sha>` 然后 `git push`（保留历史，不改写）。
- 待办跟踪：全部走 Issues，标题用 `[TODO]` 开头；做完关掉 Issue，不删。
- 每填完一节打个 tag（如 `v0.2.0`），留一个能直接回退的锚点。
